## Hard rules — never break these

1. **NO HARDCODED PRICES.** All fares, slabs, wait-charge rates, and add-on prices come
   from the backend `Pricing` collection (MongoDB). If you find a rate literal in code,
   flag it — do not add another.
2. **Server is the source of truth for time and money.** Never compute wait charges,
   final fares, or trip timestamps on the device.
3. **Emergency flow must stay fast.** No new modals, tooltips, onboarding carousels,
   or extra taps in the emergency path.
4. **No new dependencies** without asking me first — native modules force a full EAS
   rebuild (OTA won't ship them).
5. **Don't touch backend code from this repo.** If a change needs an API change,
   tell me what endpoint is needed and stop.

## Feature freeze (product decision — do not add beyond this)

The customer app is a **tracking-and-records** product, not a growth product.
Approved scope is 7 features only:

1. Live trip tracking (including trips booked by phone/call centre)
2. One-tap emergency call + location send
3. Rebook a previous trip
4. Schedule planned transport
5. Medical profile + saved addresses (with floor / lift / gate details)
6. Trip history + invoices
7. SOS during an active trip

**Not in this app:** in-app chat, wallet, loyalty points, referrals, public star
ratings, air-ambulance booking flow, blog/content, price-list browsing,
symptom checker. If a task implies one of these, ask me before building.
